# Snippet Studio V1 — 业务规则与边界条件清单

| 项目 | 内容 |
|------|------|
| 文档版本 | 1.0 |
| 编写日期 | 2026-08-08 |
| 文档性质 | 隐性业务规则显性化清单（重构后逐项回归验证） |

> 这些规则藏在原生实现与历史决策中，**UI 上不可见但破坏即出 Bug**。
> 重构 AI 必须逐条理解；Web 端与原生壳的分工标注在每条规则后。

---

## 1. 三端一致性模型（最高优先级）

**Room 数据库 ↔ Git 沙盒目录 ↔ 远程仓库**，外加**物理工作区（SAF/私有目录）**共四处数据。

| 规则 | 说明 | 分工 |
|---|---|---|
| R1.1 | 所有用户写操作（新建/编辑/重命名/移动/删除）必须以 DB 为事实来源，随后联动 Git 沙盒与物理工作区 | 原生（Repository 已有） |
| R1.2 | `autoSyncEnabled=true` 时，DB 变更后自动触发沙盒 commit+push；gitUrl 为空时跳过 push 但 commit 仍执行 | 原生 |
| R1.3 | 应用生命周期节点（onResume/onPause）触发一致性对齐扫描 | 原生（MainActivity 保留逻辑） |
| R1.4 | Web 端**只通过 Bridge 写数据**，任何绕过 Bridge 的本地缓存写入都会破坏三端一致性 | Web 约束 |

## 2. 回收站机制（.trash/）

| 规则 | 说明 |
|---|---|
| R2.1 | 软删除：`trashed=true` + `trashedAt=当前时间`；物理文件移入工作区隐藏目录 `.trash/`，Git 沙盒同步删除该文件 |
| R2.2 | 恢复：从 `.trash/` 移回原目录（`folder/fileName`），Git 沙盒重新写入 |
| R2.3 | 彻底删除：DB purge + `.trash/` 物理删除 + 沙盒删除，三处同时清除 |
| R2.4 | 过期清理：`trashedAt` 距今 > 30 天（可配）自动彻底清除；触发时机为应用启动阶段 |
| R2.5 | `.trash/` 以点号开头，**不参与 Git 同步**（见 R3.1），故回收站数据不会被推送到远端 |

## 3. Git 同步规则

| 规则 | 说明 |
|---|---|
| R3.1 | 同步范围过滤：点号（`.`）开头的文件和目录一律跳过（含 `.trash/`、`.git/` 等） |
| R3.2 | JGit `cloneRepository` 要求目标目录**不存在**；克隆前不得预创建沙盒目录 |
| R3.3 | 双按钮职责分离：①「校验连接并初始化/克隆」= 一次性配置（网络验证→沙盒克隆→DB↔沙盒双向同步，**不写物理工作区**）；②「手动完整同步 Pull & Push」= 日常全链路同步，并把 DB 全量回写物理工作区（含文件夹结构） |
| R3.4 | 已知设计缺陷（重构时保持现状，不得自行"修复"）：首次克隆后远端内容仅落 DB+沙盒，未落地物理磁盘 |
| R3.5 | 全空仓熔断：仅当 DB 中存在记录（活动>0 或回收站>0）时，才允许执行镜像清理 `cleanDeletedFiles`；全新安装空库时禁止擦除刚克隆的文件 |
| R3.6 | Pull 精准销毁：远端删除的文件按 `remoteDeletedPaths` 清单擦除物理文件并 purge DB 记录，**绝不盲删用户手动添加的文件** |
| R3.7 | 冲突检测：本地与远端同路径文件内容不一致时进入 `SyncConflict`，用户须对每个冲突选择 KEEP_LOCAL / KEEP_REMOTE / KEEP_BOTH 后方可执行 |
| R3.8 | KEEP_BOTH 策略：远端版本重命名保存（不覆盖本地） |
| R3.9 | 同步预览必须先于执行：previewPull/previewPush → 用户确认 → execute；无变更时明确提示"无变更" |
| R3.10 | PAT 鉴权失败、网络失败须给出可读错误提示，且不改变本地数据状态 |

## 4. 文件与路径规则

| 规则 | 说明 |
|---|---|
| R4.1 | 工作区双模式：`repoTreeUri` 非空走 SAF DocumentFile；为空降级应用私有目录 `getExternalFilesDir("snippets")` |
| R4.2 | SAF 授权失效（Uri 无法解析）时须提示用户重新选择目录，不得静默降级覆盖数据 |
| R4.3 | 重命名片段（fileName 变更）：先删除旧路径的 Git 沙盒与物理文件，再写入新路径——防止推送预览出现"幽灵文件" |
| R4.4 | 移动片段（folder 变更）：同样清理旧路径残留，新路径所在文件夹自动 upsert 进 folders 表 |
| R4.5 | 文件名安全化：非法字符 → `_`，合并连续下划线，截断 20 字符（见数据模型文档 §3） |
| R4.6 | 文件编码按 `encoding` 设置读写；换行符按 `lineEnding` 处理（编辑器保存时转换） |

## 5. 新建与编辑规则

| 规则 | 说明 |
|---|---|
| R5.1 | 空状态自动清理：新建片段后若标题与内容均未修改，返回时**彻底删除**该空片段，不留残留 |
| R5.2 | `useBoilerplate=true` 时新建注入 `assets/templates/template_{type}` 样板内容 |
| R5.3 | 默认标题 `{类型显示名}_{MMdd_HHmm}`；默认文件名由标题安全化生成 |
| R5.4 | 编辑器离开前未保存内容必须落库（原实现在生命周期中处理；Web 端须在路由离开/返回键时经 Bridge 保存） |
| R5.5 | 标签以逗号分隔串存储，读取 split+trim；标签内禁止包含逗号 |

## 6. Prompt 与搜索规则

| 规则 | 说明 |
|---|---|
| R6.1 | Prompt 变量识别：`{{variable}}` 占位符，变量名去重后进入 VariableFillPanel；填充后仅影响预览/复制，不改写原文 |
| R6.2 | 搜索为模糊匹配（FuzzySearchUtil），命中关键字在列表中高亮（SearchHighlighter）；Web 端可用等价算法，但命中判定结果须与原实现一致（大小写不敏感） |
| R6.3 | 类型过滤、星标过滤、标签过滤可叠加 |

## 7. 分享与剪贴板规则

| 规则 | 说明 |
|---|---|
| R7.1 | 系统分享文本/文件进入应用：`shareAction=panel` 弹快速编辑面板，`silent` 静默保存 |
| R7.2 | 分享文件类型按扩展名推断（SnippetType.fromFileName）；不可识别类型走 general |
| R7.3 | 剪贴板检测：进入首页时检测疑似代码/文本内容并提示导入；用户"忽略"后同一内容不再提示（忽略列表持久化） |
| R7.4 | 临时预览页（不落库）用于分享文件先看后存，大文本走临时缓存引用（Bridge cache 协议） |

## 8. 主题与多语言规则

| 规则 | 说明 |
|---|---|
| R8.1 | 明暗模式 `system` 时跟随系统，系统切换须实时响应（Web 端监听 `prefers-color-scheme` + settingsChanged） |
| R8.2 | 配色主题切换即时生效、无需重启；Markdown 类型图标随配色切换变体 |
| R8.3 | 语言切换 zh/en/ja 即时生效；词条以 `strings.xml` 为唯一事实来源 |
| R8.4 | 状态栏/导航栏颜色随主题明暗联动（原 SystemUiUtil；Web 版由原生壳根据 data-mode 设置） |

## 9. 验收方式

以上每条规则对应一条测试用例，执行重构的 AI 在每阶段交付时须输出**规则覆盖自查表**（规则编号 + 实现位置 + 自测结果），由用户在真机上抽验。
