## 0. 交接须知（给执行重构的 AI）

**阅读顺序（每次会话开始前必读）：**
1. `RULES.md` — 协作规范（中文注释、先解答后修改、中文提交信息）
2. `00_WebView重构技术决策书.md` — 硬性约束

5. `docs/delivery/01_产品功能规格说明书.md` — 功能验收基准
6. 其余文档按需查阅

**工作方式要求：**
- 严格按阶段顺序推进，每阶段完成须输出：代码 + 规则覆盖自查表 + 自测说明；
- 每阶段验收通过后才可进入下一阶段；
- 不得改动决策书 §1.3 列出的保留层文件；
- 遇到契约文档未覆盖的场景，先提出补充协议草案，经确认后再实现。

## 阶段 1：壳工程与 Bridge 骨架

**交付物：**
- `web-src/` React 工程初始化（Vite + TS + React Router Hash + Zustand + CodeMirror 依赖就位）
- 构建产物输出并加载于 `assets/web/`，应用启动显示占位页
- 原生 `bridge/JsBridge.kt` 骨架：invoke 入口、callId 回传、事件总线 `BridgeEventBus`
- 打通最小闭环：Web 调用 `settings.get` 成功返回并渲染

**验收：**
- [ ] 冷启动 WebView 正常加载本地页面，无网络请求
- [ ] `settings.get` / `app.version` 双向调用成功
- [ ] Native→JS 事件 `settingsChanged` 可被 Web 端接收

## 阶段 2：设计系统与静态 UI 还原

**交付物：**
- CSS 变量体系（02 文档 §3 全量令牌，6 主题 × 明暗）
- 主题切换 Hook（data-color/data-mode，system 跟随）
- 基础组件库：Button/Chip/Card/Dialog/Sheet/Switch/SegmentedControl/EmptyState 等（对照 02 文档 §2）
- 全部页面静态还原（Mock 数据）：首页/文件页/编辑器/详情/设置/子页面/历史/临时预览
- 图标 SVG 转换完成
- i18n 词条迁移（zh/en/ja）

**验收：**
- [ ] 与基线截图逐页对照通过（02 文档 §5）
- [ ] 6 配色 × 明暗全部组合无错色
- [ ] 三语切换无缺失词条

## 阶段 3：数据接入（片段与文件夹）

**交付物：**
- Bridge 客户端封装（bridge.call / on/off / 超时 / 错误码处理）

- 首页/文件页接入真实数据：列表、搜索高亮、过滤、星标、标签、视图切换
- 事件驱动刷新（dataChanged）
- 对话框流程：重命名/移动/标签编辑/新建文件夹/删除确认

**验收：**
- [ ] 01 文档功能规格"片段管理"全部 CRUD 行为一致（含 R4.3/R4.4 残留清理）
- [ ] 回收站全流程（R2.1–R2.5）+ 30 天过期清理
- [ ] 空状态自动清理（R5.1）

## 阶段 4：编辑器页

**验收：**

## 附：关键风险检查点（每阶段结束强制自检）

1. 是否有任何代码绕过 Bridge 直接写 localStorage 主数据？→ 有即返工
2. 是否改动了保留层文件（data/、util/ 业务逻辑）？→ 有即回滚
3. Bridge 新增接口是否已同步更新契约文档？→ 未更新须补
4. 主题令牌是否出现硬编码色值？→ 有即替换为 CSS 变量
