## 1. Room 数据库

- 数据库文件：`databases/snippet_studio.db`（应用沙盒内）
- 当前版本：**3**（已含 MIGRATION_1_2、MIGRATION_2_3）
- 重构要求：**版本号与迁移脚本保持不变**；除非 Web 端确有新增持久化需求（应优先放 DataStore/localStorage，避免动表）

### 1.1 表 `snippets`（片段主表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | UUID |
| type | TEXT | NOT NULL | 类型 code：`html`/`js`/`markdown`/`prompt`/`java`/`general` |
| title | TEXT | NOT NULL | 标题（可空串，展示时回退 displayTitle） |
| fileName | TEXT | NOT NULL | 物理文件名（含扩展名） |
| content | TEXT | NOT NULL | 正文全文 |
| tags | TEXT | NOT NULL DEFAULT '' | 逗号分隔标签串，如 `"UI,API"`（读取时 split+trim） |
| starred | INTEGER(bool) | NOT NULL DEFAULT 0 | 星标 |
| createdAt | INTEGER | NOT NULL | 创建时间戳（毫秒） |
| updatedAt | INTEGER | NOT NULL | 修改时间戳（毫秒） |
| sizeBytes | INTEGER | NOT NULL | 内容字节数 |
| folder | TEXT | NOT NULL DEFAULT '' | 所属文件夹相对路径（v2 迁移新增列） |
| trashed | INTEGER(bool) | NOT NULL DEFAULT 0 | 是否在回收站 |
| trashedAt | INTEGER | NULL | 入回收站时间戳（过期清理依据） |

### 1.2 表 `folders`（文件夹元数据表，v3 新增）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| path | TEXT | PK | 相对路径，如 `utils/string` |
| parentPath | TEXT | NOT NULL DEFAULT '' | 父路径（`utils/string` → `utils`） |
| createdAt | INTEGER | NOT NULL DEFAULT 0 | 创建时间戳 |

> 该表解决"物理空文件夹在 DB 无记录"的问题，Web 端文件页树形结构需合并
> `folders` 表与片段实际路径推导出的目录集合。

## 3. 领域枚举汇总

| 枚举 | 取值 | 说明 |
|---|---|---|
| SnippetType | html / js / markdown / prompt / java / general | 默认扩展名：.html/.js/.md/.txt/.java/.txt；`fromFileName` 映射规则见 `Snippet.kt`（.htm→html，.jsx/.ts/.tsx/.mjs→js 等） |
| SyncChangeType | ADDED / UPDATED / DELETED | 同步变更类型 |
| SyncDirection | INCOMING / OUTGOING | Pull 入站 / Push 出站 |
| ConflictResolution | PENDING / KEEP_LOCAL / KEEP_REMOTE / KEEP_BOTH | 冲突解决策略 |
| DiffType | ADD / DELETE / CONTEXT | Diff 行类型 |

**文件名安全化规则（`Snippet.defaultFileName`）：**
仅保留 `[a-zA-Z0-9_\-一-龥]`，其余替换为 `_` 并合并连续下划线，截取前 20 字符，
拼接类型扩展名；标题为空时用 `snippet{扩展名}`。Web 端新建/重命名时须复用同一规则。

**默认标题规则：** `{类型显示名}_{MMdd_HHmm}`（如 `Prompt_0808_1503`）。

## 4. 三端物理存储布局

| 端 | 位置 | 说明 |
|---|---|---|
| 数据库 | 沙盒 `databases/snippet_studio.db` | 索引中枢 |
| 物理工作区 | SAF 授权目录（`repoTreeUri`）或内部私有目录（降级） | 用户真实可见文件 |
| Git 沙盒 | 应用私有目录内 JGit 工作树 | 仅用于 commit/push/pull |
| 回收站 | 工作区内隐藏目录 `.trash/` | 软删除物理文件暂存 |

同步规则：点号开头文件/目录不参与 Git 同步；详见《04_业务规则与边界条件清单》。

## 5. 升级迁移方案（老用户覆盖安装）

### 5.1 零迁移策略（推荐，已拍板）
| 项 | 决策 |
|---|---|
| 包名 | 保持 `com.feige.snippetstudio` 不变 |
| versionCode | 正常递增 |
| Room | 结构/版本不变，数据原样可读 |
| DataStore | 键名不变，设置原样可读 |
| SAF 授权 | Uri 持久化于 DataStore，授权不失效 |
| 物理文件 | 位置不变，无需移动 |

**结论：老用户覆盖安装后无需任何迁移动作。**

### 5.2 强制回归测试清单（重构发版前必测）
1. 旧版本（Compose 版）安装 → 造数：≥10 条各类型片段、多层文件夹、星标、标签、回收站内数据、已绑定 Git 仓库、SAF 外部目录绑定；
2. 覆盖安装新版本（WebView 版）→ 验证：
   - [ ] 全部片段可见、内容一致（抽查逐字节比对）
   - [ ] 文件夹树结构一致（含空文件夹）
   - [ ] 设置项逐项一致（含 PAT、主题、语言）
   - [ ] SAF 目录授权仍然有效，文件可读可写
   - [ ] Git 连通状态保持，可正常 pull/push
   - [ ] 回收站数据与 trashedAt 时间保留
3. 反向验证：新版写入数据后，数据库字段格式与旧版兼容（tags 逗号串、时间戳毫秒）。

### 5.3 回滚预案
若新版出现致命问题，用户可卸载前导出（`file.exportJson/Zip`），或降级回旧 APK（数据层未变，双向兼容）。

## 6. Web 端本地存储使用边界

| 数据 | 存储位置 | 禁止事项 |
|---|---|---|
| 片段/文件夹 | Room（经 Bridge） | ❌ 禁止在 localStorage/IndexedDB 复制一份主数据 |
| 设置 | DataStore（经 Bridge） | ❌ 禁止 Web 端另存设置副本作为事实来源 |
| 视图模式等纯 UI 偏好 | localStorage | ✅ 允许，但不得与 AppSettings 字段冲突 |
| 编辑中未保存草稿 | 内存 + 可选 sessionStorage | 页面销毁前须经 Bridge 落库 |
